## Nandi 0.2.0

Download from https://vaultdb.ai (or below). Requires Docker.

Nandi 0.2.0 brings Nandi, your default agent, email-first setup, and working with teammates through your own relay, with every request sealed end to end. It also tightens what packs, connectors and agents may do before you say yes. The full list is in [CHANGELOG.md](https://github.com/vaultdbai/nandi/blob/v0.2.0/CHANGELOG.md).

### Headline changes

- **Nandi, the default agent.** The Chief of Staff is now Nandi, with its own page and Reset to defaults. Updates to its instructions reach you when you never edited them; edited files are offered with a diff.
- **Email first.** Connect Outlook or Gmail at setup. Nandi keeps My notes from your mail and acts on what arrives. Your connected email is your identity: no separate sign-in screens.
- **Inbox chats and Decisions.** Every Inbox item opens a chat with Nandi, and a Decisions page keeps one record of what you decided.
- **Runs plan and keep evidence.** Every run plans first, finishes its plan and keeps the evidence. Agents learn playbooks from "remember how I do this".
- **Teams through your relay.** The relay routes requests, stores and forwards work, fails over, reassigns and hands over by calendar. Content is sealed with per-device keys; the relay reads metadata only. Groups have signed policies the relay enforces.
- **The public relay.** Join VaultDB.ai's public relay with your connected email.
- **Connectors and the browser.** Connector packages with grants while agents work, calendars and files, a built-in Browser agent and "allow this site?".
- **Images are pulled, not built.** Signed sandbox images download with progress. Claude Code is fetched on first use.
- **Windows.** A per-user `setup.exe` that needs no admin rights, and an `.msi` for IT.

### Upgrading from 0.1.0

The upgrade is automatic. Install 0.2.0 over 0.1.0, or accept the update.

- `state.db` upgrades in place. Nandi keeps a copy first as `state.db.bak-v2`.
- Your Chief of Staff becomes Nandi, with your edits kept. The change is one commit in your gold copy: "Upgrade from Nandi 0.1.0".
- If you joined a relay, you don't join again. Nandi moves your instance token from `state.db` to the OS keyring.
- Older audit entries are kept. Logs 0.1.0 wrote are set aside as `<name>.pre-chain.log`, and Settings › Logs says "Older entries kept".

### What changed for you

- **Codex needs an OpenAI API key.** Add one in Nandi, or set `CODEX_API_KEY` or `OPENAI_API_KEY`. A ChatGPT login and Azure OpenAI can't be used in the container.
- **Gemini CLI is refused in containers** until it has a proxy route. Each of its sign-ins would put a credential in the container.
- **Public relays need a licence.** A relay started with `--public` needs a public-relay licence file. Company relays are unchanged.
- **Consent covers connectors and folders.** First-use consent now includes connectors, shared folders and their access, and taking tasks from others. An update that adds or widens any of them asks you again.
- **Packs fail closed from the default registry.** An unsigned entry, a bad signature, a branch ref or a moved tag is refused. VaultDB.ai's key ships in the app, and other publishers' keys are pinned on first install.

### Known issues

- **Update your relay with the app.** 0.2.0 speaks relay protocol 7 and 0.1.0 spoke protocol 2, so a 0.1.0 Nandi can't join a 0.2.0 relay and the reverse. From 0.2.0 on, each release works with the one before it.
- **Early relay databases.** A `relay.db` written by a relay image from before the migration baseline (version 1 to 6) is refused by the 0.2.0 relay. Move it aside; members enroll again.
- **Claude Code on a subscription sign-in** in the container is not yet verified end to end.
- **Gemini CLI** can't run in the container yet (see above).
- **Codex** can't use a ChatGPT login or Azure OpenAI.

### Installation

- **macOS**: download the `.dmg` and drag Nandi to Applications.
- **Windows**: `-setup.exe` (no admin rights needed) or `.msi` for IT deployment (`msiexec /i VaultDB-Nandi-windows-x64.msi /qn`).
- **Linux**: download the `.AppImage`, make it executable (`chmod +x`) and run it.

Existing users get an update notification once this release is published.
