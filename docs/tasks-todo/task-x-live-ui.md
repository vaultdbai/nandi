# Task: The screen always shows the latest, whoever changed it

**From:** owner, 2026-11-04: "When files change on disk, such as someone editing or adding new files, the UI doesn't refresh and show new things. Maybe there should be a refresh button somewhere, or a file watcher that keeps the UI up to date when files, agents, notes and so on change, with events so the user knows the latest done by many agents, workflows or manual edits."
**Size:** M.
**Repo:** `nandi` (app). Moved into `nandi/docs/tasks-todo/` when work started (2026-11-05, branch `live-ui`).
**Builds on:** the repo watcher (`src-tauri/src/services/watcher.rs`: debounced events for agents, workflows, triggers, capabilities and policies under `.nandi/`, published as `repo://*` events), the event bus (`services/events.rs`) and the frontend event bridge (`src/lib/client/events.ts`, `src/lib/agent-sync.ts`).
**Design:** [docs/developer/live-ui.md](../developer/live-ui.md). **Catalog:** DT-43 to DT-47.

## Changes

- [x] Watch what isn't watched yet, starting with My notes and agents' work folders (debounced; ignore editor temp files; never watch outside the Nandi folders). Done: `services/live/folders.rs` for notes and work folders; the repo watcher now reports `installed.yaml` and `NANDI.md` too. Never a drive root or the home folder (`folders::watchable`).
- [x] Every watched change publishes a typed event; the frontend invalidates exactly the queries that event affects (TanStack Query keys), so open screens update by themselves without a reload. Done: `live://changed` (`LiveChange`), `queryKeysFor` in `src/lib/live-changes.ts`. My notes no longer polls.
- [x] A small, calm "Updated just now by …" line where it helps (notes, agent pages): "by you", "by Chief of Staff", "by the Weekly report workflow", or "outside Nandi" for manual edits, so the person knows who changed what. Done: `UpdatedBy`.
- [x] An activity list (on Home or the companion) of recent changes by agents, workflows and manual edits, linking to each. Done: Home › Recent changes (`RecentChanges`).
- [x] A **Refresh** button (and F5 / Ctrl+R in the app window) on screens backed by files, as a fallback when the watcher misses something (network drives, sleeping laptops). It re-reads from disk, not just from the cache. Done: My notes, an agent's page, Workflows, Triggers, Home's list, F5, Ctrl/Cmd+R and a palette command (`refresh_from_disk`).
- [x] Handle watcher limits: if the operating system drops events (too many changes at once, a folder replaced by a git checkout), re-scan that area and say so in the log. Done: a rescan flag, a watcher error, or more than 512 paths in one batch re-scans the area and logs `Re-scanning <folder>: <why>`.

## Acceptance

- [x] Editing a note, an agent's skill.md or a workflow in an outside editor updates the open screen within about a second, with no reload. (Automated for notes and skill.md with real folders; the Notepad check is by hand.)
- [x] Files added by an agent or workflow appear without a reload, with who made them (Home › Recent changes).
- [x] The Refresh button brings every screen up to date even with the watcher switched off (a test: `live/tests.rs` `refresh_works_with_the_watcher_off`).
- [x] Testing catalog entries added ("Needs relay: no"), `pnpm run check:all` and `pnpm run test:offline` pass.

## Follow-ups (not done here)

- [ ] Who wrote a note is the run going at the time, not the exact writer. To be exact, the `filesystem` connector would need to know the calling run.
- [ ] The recent list is in memory: a restart empties it. Keep it in SQLite if people want history.
- [ ] A note open in Edit with unsaved text keeps the draft when the file changes underneath. Say "Changed outside Nandi while you were editing" and offer to reload.
- [ ] Re-pointing `my-notes` to another folder starts watching it the next time My notes opens (or at the next start), not at once.
- [ ] The gateway still polls `NANDI.md` every 5 s. It could use the watcher's `Target::Profile` instead.
- [ ] Refresh on waking from sleep (a window focus or resume event) instead of waiting for F5.
